# Governance

Governance is transversal to the workflow.

It is not an independent phase.

## Core Governance

These rules are always part of the process:

* Decision Control;
* Failure Routing;
* Change Control;
* Drift Control;
* Traceability;
* Lifecycle / Locked.

## Conditional Governance

Activated only when the context requires it:

* Security;
* Performance;
* Migration;
* Backtest;
* Visual;
* Compliance;
* Model Evaluation.

Other controls may be added when the context justifies them, without automatically turning them into workflow phases.

## Principle

Governance must control the process without introducing artificial work.

Rigor must adapt to real risk and complexity.
